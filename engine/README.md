# Engine / 엔진

The engine is an internal, deterministic FastAPI service (package `antlab_engine`). Its HTTP contract is `docs/api/engine.yaml`; every route except `GET /healthz` needs the `X-Antlab-Engine-Token` header.
엔진은 내부 전용 결정적 FastAPI 서비스(패키지 `antlab_engine`)다. HTTP 계약은 `docs/api/engine.yaml`이며, `GET /healthz`를 뺀 모든 경로는 `X-Antlab-Engine-Token` 헤더가 필요하다.

## Metrics / 지표

The replay start is read from `ANTLAB_HISTORY_REPLAY_START` (first day of a month as `YYYY-MM-DD`, default `2007-01-01`, the same name and rule as the api setting `antlab.history.replay-start`); a malformed or mid-month value fails startup and names the variable. Paths, projections, percentiles and their history digests use it, and `GET /v1/info` reports it as `replayStart`; the api compares the two before each engine path, projection or percentile call. / 재생 시작은 `ANTLAB_HISTORY_REPLAY_START`(달의 1일, `YYYY-MM-DD`, 기본 `2007-01-01`, api 설정 `antlab.history.replay-start`와 같은 이름·규칙)에서 읽는다. 형식이 틀리거나 달 중간이면 시작이 실패하고 변수 이름을 알린다. 경로·예상 분포·순위와 이력 해시가 이 값을 쓰고 `GET /v1/info`가 `replayStart`로 알리며, api는 엔진 경로·예상 분포·순위 호출마다 먼저 둘을 비교한다.

The engine serves Prometheus metrics on a separate internal port, 8001 (`ANTLAB_ENGINE_METRICS_PORT`), with no token and a different listener from the API. Compose never publishes 8001; Prometheus job `antlab-engine` scrapes `engine:8001` on the `backend` network and the dashboard is `antlab-engine`. The bind address is `ANTLAB_ENGINE_METRICS_HOST`, default `127.0.0.1` for native runs; the compose service sets `0.0.0.0` inside the container. Run exactly one worker: each worker owns its own registry and port, so `--workers` above 1 or `WEB_CONCURRENCY` above 1 is refused at startup (a second bind fails with a message). Labels are the matched route template, a fixed method set plus `OTHER`, and the status (or status class on the duration histogram); path values, queries and tokens never appear. `process_*` metrics export on Linux only (the container).
엔진은 Prometheus 지표를 API와 다른 내부 포트 8001(`ANTLAB_ENGINE_METRICS_PORT`)에 토큰 없이 낸다. compose는 8001을 게시하지 않고, Prometheus 잡 `antlab-engine`이 `backend` 네트워크에서 `engine:8001`을 긁으며 대시보드는 `antlab-engine`이다. 바인드 주소는 `ANTLAB_ENGINE_METRICS_HOST`이고 로컬 실행의 기본은 `127.0.0.1`이며, compose 서비스는 컨테이너 안에서 `0.0.0.0`으로 정한다. 워커는 정확히 하나만 쓴다. 워커마다 자기 레지스트리와 포트를 가지므로 `--workers` 또는 `WEB_CONCURRENCY`가 1보다 크면 기동 때 거부한다(두 번째 바인드는 메시지와 함께 실패한다). 라벨은 매칭된 경로 템플릿, 고정 메서드 집합과 `OTHER`, 상태(처리 시간 히스토그램은 상태 계열)이며 경로 값·쿼리·토큰은 나오지 않는다. `process_*` 지표는 Linux(컨테이너)에서만 나온다.

## Database / 데이터베이스

The engine reads history as the SELECT-only role `antlab_engine` (created by `db/roles/antlab_engine.sql`, see `db/README.md`; Java alone writes the database). Settings come from the environment: `ANTLAB_ENGINE_DB_HOST`, `ANTLAB_ENGINE_DB_NAME` and `ANTLAB_ENGINE_DB_USER` are required (a missing or blank value fails startup and names the variable, never the value), `ANTLAB_ENGINE_DB_PORT` defaults to 5432, and `ANTLAB_ENGINE_DB_PASSWORD` is optional locally and never printed. Startup and `/healthz` open no connection. `antlab_engine.history.PostgresHistoryReader.read(base_date)` returns one frozen snapshot from a single `REPEATABLE READ READ ONLY` transaction: months strictly before 1 January of the base year, the pool of that exact base date, and local returns and FX changes for those assets and months, all as `Decimal`. It refuses a superuser, a role that can create roles or databases or bypass row security, and any role holding a write privilege on any ordinary table outside the system schemas (`UNSAFE_DB_ROLE`), and errors never echo the cause, the password or a month. The connection uses explicit parameters, so libpq `PG*` variables (including `PGHOSTADDR`, `PGPASSWORD` and `PGGSSENCMODE`) and password files do not apply. Only `POST /v1/paths` returns months (internal route). / 엔진은 SELECT만 가진 역할 `antlab_engine`(`db/roles/antlab_engine.sql`이 만든다, `db/README.md` 참고. 데이터베이스는 Java만 쓴다)으로 이력을 읽는다. 설정은 환경변수에서 읽는다: `ANTLAB_ENGINE_DB_HOST`·`ANTLAB_ENGINE_DB_NAME`·`ANTLAB_ENGINE_DB_USER`는 필수(없거나 비어 있으면 시작이 실패하고 값이 아니라 변수 이름만 알린다), `ANTLAB_ENGINE_DB_PORT` 기본값은 5432, `ANTLAB_ENGINE_DB_PASSWORD`는 로컬에서 선택이며 출력하지 않는다. 시작과 `/healthz`는 연결을 열지 않는다. `antlab_engine.history.PostgresHistoryReader.read(base_date)`는 `REPEATABLE READ READ ONLY` 트랜잭션 하나에서 얼린 스냅샷을 돌려준다: 기준 연도 1월 1일 이전의 달, 그 기준일의 풀, 그 종목·달의 현지 수익률과 환율 변화를 모두 `Decimal`로 준다. 슈퍼유저, 역할·데이터베이스 생성 또는 행 보안 우회 권한이 있는 역할, 시스템 스키마 밖의 어느 일반 표에든 쓰기 권한이 있는 역할이면 거부하고(`UNSAFE_DB_ROLE`), 오류에는 원인·비밀번호·달을 싣지 않는다. 연결은 명시한 매개변수만 써서 libpq `PG*` 변수와 비밀번호 파일이 적용되지 않는다. 달을 돌려주는 경로는 내부 전용 `POST /v1/paths`뿐이다.

Smoke check (counts and session facts only, no dates). / 스모크 확인(건수와 세션 정보만, 날짜 없음).

## Bootstrap parity / 부트스트랩 대사

`antlab_engine.bootstrap` is a bit-exact Python port of `p0-boot6-v1` (`SplitMix64` and the month selection of the Java `SimpleBootstrap`). `POST /v1/paths` serves it. `tests/test_vectors.py` reads the tracked Java vector file `src/test/resources/engine/p0-boot6-v1_vectors.csv` in place and compares every row character for character; a missing file fails the test. Changing any constant or formula changes the paths, so the engine version must change with the vectors. / `antlab_engine.bootstrap`은 `p0-boot6-v1`(`SplitMix64`와 Java `SimpleBootstrap`의 달 선택)을 비트 단위로 같게 옮긴 Python 라이브러리이며 `POST /v1/paths`가 이를 제공한다. `tests/test_vectors.py`는 추적되는 Java 벡터 파일 `src/test/resources/engine/p0-boot6-v1_vectors.csv`를 제자리에서 읽어 모든 행을 글자 단위로 비교하고, 파일이 없으면 시험이 실패한다. 상수나 식이 바뀌면 경로가 달라지므로 벡터와 함께 엔진 판을 올려야 한다.

## Price parity / 가격 대사

The same seed must give the same months and the same won price in Java and Python. Three tracked files under `src/test/resources/engine/parity/` pin this, each with one writer: `inputs-v1.csv` (hand-designed synthetic returns, read by both sides), `p0-prices-v1.csv` (written by Java `PriceParityVectorsTest`; rewrite it by running that class once with `ANTLAB_PARITY_WRITE=1`) and `m2-prices-v1.csv` (written by `tests/make_m2_price_vectors.py`: `uv run --frozen python tests/make_m2_price_vectors.py > ../src/test/resources/engine/parity/m2-prices-v1.csv`; review the diff as data). `tests/test_price_parity.py` picks the `p0-boot6-v1` months with the Python port and multiplies with an exact `Decimal` (the `Inexact` trap proves no digit was lost), rounding half up to a whole won once, as `MoneyMath.priceAt` does; it also checks that the projection library's float64 value multiple stays within 1e-9 of the exact factor. `tests/test_m2_price_vectors.py` drift-tests the Python-owned file, and Java `M2PriceVectorsTest` recomputes every won from it. An opt-in Java test, `EngineLiveParityTest`, compares the months a running engine returns with the Java bootstrap on the same database; it is skipped unless `ANTLAB_ENGINE_LIVE_URL`, `ANTLAB_ENGINE_LIVE_TOKEN` and `ANTLAB_ENGINE_LIVE_DB_URL` are set, and it refuses anything but loopback on a port from 56100 up. / 같은 시드는 Java와 Python에서 같은 달과 같은 원화 가격을 내야 한다. `src/test/resources/engine/parity/`의 추적 파일 셋이 이를 고정하고 파일마다 쓰는 쪽이 하나다: `inputs-v1.csv`(손으로 설계한 합성 수익률, 양쪽이 읽는다), `p0-prices-v1.csv`(Java `PriceParityVectorsTest`가 쓴다. 다시 쓰려면 이 클래스를 `ANTLAB_PARITY_WRITE=1`로 한 번 실행한다), `m2-prices-v1.csv`(`tests/make_m2_price_vectors.py`가 쓴다: `uv run --frozen python tests/make_m2_price_vectors.py > ../src/test/resources/engine/parity/m2-prices-v1.csv`, 차이는 데이터로 검토한다). `tests/test_price_parity.py`는 Python 이식본으로 `p0-boot6-v1` 달을 고르고 정확한 `Decimal`로 곱해(`Inexact` 함정이 한 자리도 잃지 않았음을 보인다) `MoneyMath.priceAt`처럼 원 단위로 마지막에 한 번 반올림(0.5는 올림)하며, 예상 분포 라이브러리의 float64 가치 배수가 정확한 계수와 1e-9 이내인지도 본다. `tests/test_m2_price_vectors.py`는 Python이 쓰는 파일의 변경을 감시하고, Java `M2PriceVectorsTest`가 그 파일의 모든 가격을 다시 계산한다. 선택 실행하는 Java 시험 `EngineLiveParityTest`는 실행 중인 엔진이 돌려주는 달을 같은 DB의 Java 부트스트랩과 비교한다. `ANTLAB_ENGINE_LIVE_URL`·`ANTLAB_ENGINE_LIVE_TOKEN`·`ANTLAB_ENGINE_LIVE_DB_URL`이 없으면 건너뛰고, 포트 56100 이상의 루프백이 아니면 거부한다.

## Feed parity / 피드 대사

`antlab_engine.sim.feed` is a Python port of the feed row selection, the ranking board and the turn signals (rule version `p0-18:v2`, no body text). Java is the oracle: `FeedVectorsTest` writes `src/test/resources/feed/vectors-v1.jsonl` (rewrite with `ANTLAB_PARITY_WRITE=1 ./gradlew test --tests antlab.feed.FeedVectorsTest`; refused under CI) and fails on a stale file. `tests/test_feed_vectors.py` reads it in place and requires the same rows, variable text, boards, signals and refusal classes; it first checks that the rule version and the sha256 of the five `feed/*.csv` files equal the file's header, so a changed catalog fails until the vectors are regenerated. / `antlab_engine.sim.feed`는 피드 행 선택, 순위판, 턴 신호(규칙 버전 `p0-18:v2`, 본문 글 없음)를 옮긴 Python 이식본이다. 정답은 Java다. `FeedVectorsTest`가 `src/test/resources/feed/vectors-v1.jsonl`을 쓰고(다시 쓰기는 `ANTLAB_PARITY_WRITE=1 ./gradlew test --tests antlab.feed.FeedVectorsTest`, CI에서는 거부) 낡은 파일이면 실패한다. `tests/test_feed_vectors.py`는 이 파일을 제자리에서 읽어 행, 변수 글, 순위판, 신호, 거절 종류가 모두 같아야 통과하며, 먼저 규칙 버전과 `feed/*.csv` 다섯 파일의 sha256이 파일 머리줄과 같은지 확인하므로 카탈로그가 바뀌면 벡터를 다시 만들 때까지 실패한다.

## Stationary bootstrap / 정상 블록 부트스트랩

`antlab_engine.bootstrap.stationary` is the M2 path generator `m2-sb6-v1`: geometric block lengths (mean 6, cap 24), each block starts on the virtual calendar month (fewer than 3 candidates → ±1 month → any month), no month twice in one season, months of recent seasons avoided up to a caller threshold (a path that cannot meet it is still returned, best attempt first, with `overlap_met` false). The block length mean is 6 before the cap of 24 and about 5.92 after it. It is deterministic for a seed and pinned by `tests/vectors/m2-sb6-v1_vectors.csv`; `tests/gen_stationary_vectors.py` regenerates the file (review the diff as data). `POST /v1/paths` serves it (see below), and `p0-boot6-v1` stays unchanged. `uv run --frozen pytest -m slow -s tests/test_stationary_perf.py` prints the timing and overlap measurements. Supported history is up to about 1,200 months; one path costs under 0.15 s at the default 32 attempts even on the worst measured inputs, and the `attempts` budget is not capped in the library (256 attempts is about 1 s), so only the default is exposed over HTTP. / `antlab_engine.bootstrap.stationary`는 M2 경로 생성기 `m2-sb6-v1`이다. 블록 길이는 기하 분포(평균 6, 상한 24)이고, 블록마다 첫 달을 가상 달력의 월에 맞추며(후보 3개 미만이면 ±1개월 → 아무 달), 한 시즌에 같은 달을 두 번 쓰지 않고, 최근 시즌의 달은 호출자가 준 문턱까지 피하되, 문턱을 못 맞추면 가장 나은 시도의 경로를 `overlap_met` 거짓으로 돌려준다. 블록 길이 평균은 상한 24를 적용하기 전 6, 적용한 뒤 약 5.92이다. 같은 시드는 같은 경로를 내며 `tests/vectors/m2-sb6-v1_vectors.csv`가 고정하고, `tests/gen_stationary_vectors.py`가 이 파일을 다시 만든다(차이는 데이터로 검토한다). `POST /v1/paths`가 이를 제공하며(아래 참고) `p0-boot6-v1`은 그대로다. `uv run --frozen pytest -m slow -s tests/test_stationary_perf.py`가 시간과 겹침 측정값을 출력한다. 지원하는 이력은 약 1,200개월까지이고, 측정한 최악 입력에서도 기본 32회 시도에서 경로 하나가 0.15초 미만이다. 라이브러리는 `attempts`에 상한을 두지 않으므로(256회는 약 1초) HTTP에는 기본값만 노출한다.

## Paths endpoint / 경로 엔드포인트

`POST /v1/paths` (internal, token required; contract in `docs/api/engine.yaml`) returns one path of months for a seed from the history reader's snapshot. `engineVersion` selects `p0-boot6-v1` (fixed 6-month blocks, reproduces the Java vectors) or `m2-sb6-v1`. `seed` is a decimal string (signed 64-bit), `length` is 12, 24, 60 or 120, `baseDate` picks the snapshot, and the replay range stays 2007-01 up to the base year. `recentMonths` (`YYYY-MM`) and `maxOverlap` (decimal string, 0 to 1, default `"1"`) apply to `m2-sb6-v1` only; `conditional` must be false (regime-conditional paths are not built yet). The response has the months as `YYYY-MM`, the blocks, the overlap result, the attempt and a `historyDigest` (SHA-256 of the engine version and the sorted replayable months). Months and blocks are replay-only data: they are returned on this route only, never logged and never put into an error. Errors are `application/problem+json`: `INVALID_ARGUMENT` 400, `UNAUTHENTICATED` 401, `POOL_NOT_FOUND` 404, `PATH_TOO_LONG` 422 (the status Java uses), `HISTORY_UNAVAILABLE` 503, and `INTERNAL_ERROR` 500 (an unsafe database role is also answered this way, without role facts). `tests/test_paths_route.py` uses a fake reader; `tests/db/test_paths_db.py` runs the route against the isolated database. / `POST /v1/paths`(내부 전용, 토큰 필요, 계약은 `docs/api/engine.yaml`)는 이력 읽기 스냅샷에서 시드 하나의 달 경로를 돌려준다. `engineVersion`이 `p0-boot6-v1`(6개월 고정 블록, Java 벡터를 재현)과 `m2-sb6-v1`을 고른다. `seed`는 십진 문자열(부호 있는 64비트), `length`는 12·24·60·120, `baseDate`가 스냅샷을 정하며 재생 구간은 2007-01부터 기준 연도 직전까지로 그대로다. `recentMonths`(`YYYY-MM`)와 `maxOverlap`(0~1 십진 문자열, 기본 `"1"`)은 `m2-sb6-v1`에만 쓰이고, `conditional`은 false여야 한다(국면 조건 경로는 아직 없다). 응답은 `YYYY-MM` 달, 블록, 겹침 결과, 시도 번호, `historyDigest`(엔진 판과 정렬한 재생 가능 달의 SHA-256)이다. 달과 블록은 복기 전용 데이터라서 이 경로에서만 돌려주고, 로그와 오류에는 싣지 않는다. 오류는 `application/problem+json`이며 `INVALID_ARGUMENT` 400, `UNAUTHENTICATED` 401, `POOL_NOT_FOUND` 404, `PATH_TOO_LONG` 422(Java와 같은 상태), `HISTORY_UNAVAILABLE` 503, `INTERNAL_ERROR` 500이다(안전하지 않은 DB 역할도 역할 정보 없이 이렇게 답한다). `tests/test_paths_route.py`는 가짜 reader를, `tests/db/test_paths_db.py`는 격리 DB를 쓴다.

## Projection library / 예상 분포 라이브러리

`antlab_engine.projection.project` runs the current team as fixed quantities (buy and hold: no rebalancing, fees, interest or contributions) over N paths from `m2-sb6-v1`. Path seeds are derived from the season seed with a fixed domain constant, so the season seed is never reused and every portfolio sees the same paths. A different seed does not by itself guarantee a different path: `project` rejects a history that allows only one path (every seed would give it), but on a very short history paths can still repeat or coincide with the season's own. It returns value-multiple bands (5/25/50/75/95 %) for every turn, and at the summary turns (default 60 and 120) the end-multiple quantiles, the maximum-drawdown quantiles (5/10/25/50/75/95 %) and the number of paths whose maximum drawdown is strictly below the risk limit. It returns ratios only; Java converts to won. Quantiles are Hyndman-Fan type 7 with an exact index; evaluation uses element-wise numpy operations in sorted asset order and no matrix product, so the same inputs give the same bytes on one platform (`tests/test_projection_reference.py` compares them with a pure-Python evaluator bit for bit; `tests/test_projection_eval.py` pins the SHA-256 of a fixed input and, when it differs, prints the Python, numpy and wheel tag so arm64 and x86_64 runs can be compared; only arm64 has been checked). Decimal inputs are validated without rounding: a weight sum, a growth factor or a return that needs more than 200 significant digits is rejected, and so is a projection whose values overflow a float64 (`INVALID_ARGUMENT`, never NaN). Sizes are capped: a panel holds at most 1,200 months and 1,000 assets, a projection or seed list at most 5,000 paths. Months where a weighted asset has no return are never drawn. `POST /v1/projections` serves it (see below; `projection_version` `m2-pj-v1`). `uv run --frozen pytest -m slow -s tests/test_projection_perf.py` prints the stage timings (2,000 paths x 120 turns x 180 assets x 3 portfolios: about 0.6 s on the development Mac). / `antlab_engine.projection.project`는 현재 팀을 수량 고정(보유만 함: 재조정·수수료·이자·적립 없음)으로 `m2-sb6-v1`의 N개 경로에 돌린다. 경로 시드는 시즌 시드에서 고정 도메인 상수로 파생하므로 시즌 시드는 다시 쓰이지 않고, 모든 포트폴리오가 같은 경로를 쓴다. 시드가 다르다고 경로가 반드시 다른 것은 아니다: 이력이 경로 하나만 허용하면(모든 시드가 같은 경로를 낸다) `project`가 거부하지만, 아주 짧은 이력에서는 경로가 반복되거나 시즌 경로와 겹칠 수 있다. 매 턴의 평가 배수 분위 띠(5·25·50·75·95%)와, 요약 턴(기본 60·120)의 종료 배수 분위, 최대 낙폭 분위(5·10·25·50·75·95%), 최대 낙폭이 위험 한도보다 엄격히 깊은 경로 수를 낸다. 비율만 내고 원화 환산은 Java가 한다. 분위는 정확한 인덱스를 쓰는 Hyndman-Fan type 7이며, 평가는 정렬된 종목 순서의 numpy 원소별 연산만 쓰고 행렬 곱을 쓰지 않아 같은 플랫폼에서 같은 입력이 같은 바이트를 낸다(`tests/test_projection_reference.py`가 순수 Python 평가기와 비트 단위로 대조하고, `tests/test_projection_eval.py`가 고정 입력의 SHA-256을 고정해 두며 다를 때 Python·numpy·wheel 태그를 출력해 arm64와 x86_64 실행을 비교할 수 있게 한다. 지금까지 arm64만 확인했다). Decimal 입력은 반올림 없이 검증한다: 유효숫자 200자리를 넘는 비중 합·성장 배수·수익률은 거부하고, 값이 float64를 넘치는 예상 분포도 NaN이 아니라 `INVALID_ARGUMENT`로 거부한다. 크기에 상한이 있다: 패널은 최대 1,200개월 × 1,000종목, 예상 분포와 시드 목록은 최대 5,000경로. 비중이 있는 종목의 수익률이 없는 달은 뽑지 않는다. `POST /v1/projections`가 이를 제공한다(아래 참고, `projection_version` `m2-pj-v1`). `uv run --frozen pytest -m slow -s tests/test_projection_perf.py`가 단계별 시간을 출력한다(2,000경로 × 120턴 × 180종목 × 포트폴리오 3개: 개발용 맥에서 약 0.6초).

## Projections endpoint / 예상 분포 엔드포인트

`POST /v1/projections` (internal, token required; contract in `docs/api/engine.yaml`) projects fixed holdings over `n` paths (100 to 5,000, default 2,000) of `m2-sb6-v1` for 1 to 6 portfolios. A portfolio is a `key`, a `cash` share and up to 200 `weights` (`asset` as `MARKET:TICKER`, `weight` as a decimal string); weights plus cash must add up to exactly 1. `seasonSeed` (decimal string, signed 64-bit) only derives the path seeds, so the season's own path is never one of them; `horizonTurns` is 60 or 120, `riskLimit` is a decimal string such as `"-0.30"`, and `summaryTurns` (default 60 and 120) are capped at the horizon. The route reads the snapshot for `baseDate` from the history reader (US assets use the month's USD change, KR assets none) and draws only from months where every held asset has a return. The response gives, per portfolio, the bands for every turn and, per summary turn, the end-multiple quantiles, the maximum-drawdown quantiles, `breachCount` and `breachProbability`, all as decimal strings with eight fractional digits (rounded half up once). It has no months, no won amounts and no per-path values; `historyDigest` is the SHA-256 of the versions, the held assets and the eligible months with their growth factors. Errors are as for `/v1/paths`; the weights, the risk limit and the seed are checked before any history is read. A history that breaks the panel rules is a generic `INTERNAL_ERROR` 500. At most 3 projections run at once per process (`MAX_PROJECTIONS`, about 110 MB each in the worst case); a further call is answered `ENGINE_BUSY` 503 immediately (no queue) and may be retried. The answer carries `Retry-After: 1`. The typical case takes about 0.6 s, but the contract maximum (n = 5,000, 6 portfolios of 200 assets, 120 turns) took about 5.8 s on the development Mac with one request and longer when requests overlap (the generator is pure Python and shares the GIL), so a client should set its read timeout well above 6 s and retry with backoff on `ENGINE_BUSY` only. A multiple is never clipped and can exceed the 9,999.99999999 of `NUMERIC(12,8)`; a store needs a wider column (for example `NUMERIC(32,8)`). `historyDigest` is the SHA-256 of the stored decimals in the layout written in `engine.yaml`, not of float text. `tests/test_projections_route.py` uses a fake reader, `tests/db/test_projections_db.py` the isolated database, and `uv run --frozen pytest -m slow -s tests/test_projections_route_perf.py` prints the stage timings (2,000 paths x 120 turns x 180 assets x 3 portfolios: about 0.6 s on the development Mac, fake reader). / `POST ## Percentiles endpoint / 백분위 엔드포인트

`POST /v1/percentiles` (internal, token required; contract in `docs/api/engine.yaml`) ranks an observed season among `n` paths (100 to 5,000, default 2,000) of `m2-sb6-v1`. `team` (the season-start team) and `benchmark` are fixed holdings (`cash` and up to 200 `weights`, each summing with cash to exactly 1, no `key`) evaluated on paths drawn like those of `/v1/projections` (same seed derivation, so the season's own path is never one of them; the eligible months are those in which every asset of `team` and `benchmark` has a return, so they differ from a projection of the team alone when the benchmark holds other assets). Values are computed as `1 + sum(weight * (growth - 1))`, so holdings that never move stay at exactly 1. `horizonTurns` is 12, 24, 60 or 120. Per path the engine takes the team's end multiple and the Sharpe difference `sharpe(team) - sharpe(benchmark)` (`mean / std` with `ddof=1` of the turn returns, 0 when the deviation is 0, monthly, not annualised, summed in a fixed order). `observed.endMultiple` and `observed.sharpeDiff` are decimal strings; the answer gives, for each, integer counts `below` (strictly smaller) and `equal` (exactly equal in float64), so `below + equal <= n`. It has no months, no won amounts, no per-path values and no rounded percentile: the caller derives the percentile (mid-rank `(below + equal / 2) / n`). Errors, the `ENGINE_BUSY` limit shared with `/v1/projections`, and `historyDigest` (over the assets of both books) are as for `/v1/projections`. Measured on the development Mac (fake history, 348 months): 2 assets, n = 2,000: about 0.25 s at 12 turns and 0.5 s at 120 turns; 180 assets per book, n = 2,000, 120 turns: about 0.7 s; the contract maximum (200 assets per book, n = 5,000, 120 turns): about 2.1 s. `tests/test_rank.py` covers the library, `tests/test_percentiles_api.py` the route with a fake reader, and `tests/test_percentile_fixtures.py` the shared fixtures in `docs/api/fixtures/engine/`. / `POST /v1/percentiles`(내부 전용, 토큰 필요, 계약은 `docs/api/engine.yaml`)는 관측한 시즌이 `m2-sb6-v1`의 `n`개(100~5,000, 기본 2,000) 경로 안에서 어디에 놓이는지 센다. `team`(시즌 시작 팀)과 `benchmark`는 고정 보유(`cash`와 최대 200개의 `weights`, 각각 현금과 합쳐 정확히 1, `key` 없음)이며 `/v1/projections`와 같은 방식으로 뽑은 경로에서 평가한다(시드 파생이 같으므로 시즌 경로는 그중 하나가 아니고, 자격 있는 달은 `team`과 `benchmark`의 모든 종목에 수익률이 있는 달이라서 벤치마크가 다른 종목을 보유하면 팀만 넣은 예상 분포와 다르다). 값은 `1 + sum(비중 × (성장 배수 − 1))`로 계산하므로 움직이지 않는 보유는 정확히 1로 남는다. `horizonTurns`는 12·24·60·120이다. 경로마다 팀의 최종 배수와 샤프 차이 `sharpe(team) - sharpe(benchmark)`(턴 수익률의 `ddof=1` `mean / std`, 편차가 0이면 0, 월 단위·연율화 없음, 고정 순서로 합산)를 구한다. `observed.endMultiple`과 `observed.sharpeDiff`는 십진 문자열이고, 응답은 각각에 대해 정수 개수 `below`(엄격히 작음)와 `equal`(float64로 정확히 같음)을 주므로 `below + equal <= n`이다. 달·원화 금액·경로별 값·반올림한 백분위는 없고 백분위(중간 순위 `(below + equal / 2) / n`)는 호출 쪽이 계산한다. 오류, `/v1/projections`와 함께 쓰는 `ENGINE_BUSY` 한도, `historyDigest`(두 보유의 종목 기준)는 `/v1/projections`와 같다. 개발용 맥에서 잰 시간(가짜 이력, 348개월): 종목 2개·n = 2,000은 12턴 약 0.25초, 120턴 약 0.5초, 보유당 180종목·n = 2,000·120턴은 약 0.7초, 계약 최대(보유당 200종목·n = 5,000·120턴)는 약 2.1초. `tests/test_rank.py`는 라이브러리를, `tests/test_percentiles_api.py`는 가짜 reader로 라우트를, `tests/test_percentile_fixtures.py`는 `docs/api/fixtures/engine/`의 공유 픽스처를 다룬다.

## Regime scoring / 국면 채점

`antlab_engine.regime` is a pure library (numpy and the standard library only) that scores the 14 MACRO_ETF §2.3 indicators from point-in-time observations: rolling 5-year z-scores, axis scores, P1–P4 probabilities, hysteresis label and phase. It never uses an observation before its availability date and uses rolling statistics only. `POST /v1/regime/evaluate` (internal, token required, contract in `docs/api/engine.yaml`) serves it. `evaluate(observations, dates)` runs MACRO_ETF §2.4 once per date (weekly Saturdays from `weekly_schedule`; the EMA half life of 4, the 2-step confirmation and the 4-step hold count steps) and `month_end_sample` takes the last step inside a month for the month block. The library returns both the hysteresis directions of R and G and a three-state display (UP, DOWN or NEUTRAL inside ±0.25, strength = |score|) for all four axes; F and the sentiment axis S (indicator #13 only, the §2.6 overlay is not built) are not smoothed. Revised series use the vintage known on each date: the two US series (core CPI, jobless claims) and the three Korean monthly series (the system snapshots every collection, MACRO_ETF §2.8), so a second vintage of one reference date is accepted. The library trusts `available_on`; a Korean monthly value is also held back by its publication lag (7, 15 and 35 days after the month end), but the M2-08 adapter must store the real publication date of every US series (for example the next business day for the H.15 yields, about 5 days after the week end for jobless claims) because the weekly step on Saturday would otherwise see a value one business day early. `uv run --frozen pytest -m slow -s tests/test_regime_perf.py` prints the time of 29 years of weekly steps over the full catalog (about 3 s on the development Mac, budget 5 s). A step without fresh data for an axis carries that axis's EMA and neither counts toward nor resets the direction-flip confirmation, however long the gap lasts (a long gap is not restarted). `unavailable` lists the indicators with no usable term (stale, missing or warming) even when `quality_ok` stays true. Two collections of one Korean reference date made before its publication floor are both kept, and the later one wins. ### Regime data source / 국면 데이터 출처

With the `ANTLAB_ENGINE_DB_*` variables set, the route reads the macro tables `series` and `series_observation` through `antlab_engine.regime.pg_source.PostgresRegimeSource` as the SELECT-only `antlab_engine` role (run `db/roles/antlab_engine.sql` again after the V12 migration: it grants SELECT on ten tables since M3-02 PR D; it was seven when this route was added). One call is one `REPEATABLE READ READ ONLY` transaction and one parameterised SELECT; the SQL lives in `history/queries.py`. Each row becomes a `RawObservation` with `published_on` = `realtime_start`, else `available_on`, else (vintage 2 or later) the UTC day the revision was stored, else none (a back-filled first vintage, dated by the publication floor and counted in `ruleDatedRows`). A row that cannot be known on or before the last day of the last requested month is not read, so a later revision or release never reaches an earlier month. Only the 16 catalog codes are read, and the holiday calendars are empty (no tracked source; they only refine the stale rule). A series the library treats as not revisable (daily yields, the dollar index, Korean daily rates) is read at vintage 1 only: a later correction of such a value is ignored (point-in-time safe, and it cannot stop every later run with a 422), and the coverage report shows it as `unexpectedVintages`; the revisable series (core CPI, jobless claims, Korean CPI, CLI, exports) return every vintage. Without database settings the route answers 503 `HISTORY_UNAVAILABLE`; an unreachable or unauthorised database answers the same code and never echoes the cause. / `ANTLAB_ENGINE_DB_*` 변수가 있으면 경로는 SELECT만 가진 `antlab_engine` 역할로 `antlab_engine.regime.pg_source.PostgresRegimeSource`를 거쳐 거시 테이블 `series`와 `series_observation`을 읽는다(V12 마이그레이션 뒤 `db/roles/antlab_engine.sql`을 다시 실행한다. M3-02 PR D 뒤로는 테이블 10개의 SELECT를 준다. 이 경로를 넣을 때는 7개였다). 호출 하나는 `REPEATABLE READ READ ONLY` 트랜잭션 하나와 매개변수화한 SELECT 하나이며 SQL은 `history/queries.py`에 있다. 행마다 `RawObservation`이 되고 `published_on`은 `realtime_start`, 없으면 `available_on`, 없으면(빈티지 2 이상) 개정이 저장된 UTC 날짜, 그것도 없으면 없음(되메운 첫 빈티지는 공표 하한이 날짜를 정하고 `ruleDatedRows`에 센다)이다. 요청한 마지막 달의 말일 이전에 알려질 수 없는 행은 읽지 않으므로 나중의 개정이나 발표가 이른 달에 닿지 않는다. 카탈로그 코드 16개만 읽고 휴일 달력은 비어 있다(추적하는 출처가 없고, 낡음 판정만 다듬는다). 라이브러리가 수정되지 않는다고 보는 시계열(일별 금리, 달러지수, 한국 일별 금리)은 빈티지 1만 읽는다. 나중의 정정값은 무시하고(시점 기준으로 안전하며, 422로 이후 모든 실행을 막지 않는다) 커버리지 보고서가 `unexpectedVintages`로 보여 준다. 수정되는 시계열(근원 CPI, 실업수당 청구, 한국 CPI·CLI·수출)은 모든 빈티지를 돌려준다. 데이터베이스 설정이 없으면 503 `HISTORY_UNAVAILABLE`이고, 닿지 않거나 권한이 없을 때도 같은 코드이며 원인은 싣지 않는다.

Coverage report (counts, first and last reference dates, gaps and vintage counts per series; no values). ## Season simulator / 시즌 시뮬레이터

`antlab_engine.sim` plays one season offline from a list of decisions with the Java rules: turn prices, market fills with fees and the FX cost, the ledger, holdings and lineup spans, formation and lineup changes, abandon with auto turns, the 38-value season report and the `s63-v3` score. It is a library only: no route, no database, no network, and no `float` (money is `Decimal`, one rounding per value as in Java). Its won amounts are for backtests and never reach a stored row or a player (PLAN §5.2). Inputs are `sim-inputs/1` (settings, the pool in asset-id order with `systemPosition` as a required, nullable key, and the path returns) and the decisions are `sim-decisions/1` (`docs/api/sim-decisions-1.schema.json`); a refusal is a verdict value, only a malformed input raises. Java is the oracle at three levels: `src/test/resources/sim/money-vectors-v1.jsonl` (written by `SimMoneyVectorsTest`) pins the money kernel; `src/test/resources/sim/parity/seasons-v1.json` pins whole seasons; and the hand cases of the Java report and score tests are ported by value. `SimulatorParityFixtureTest` plays 20 seeded seasons (12 turns x 10, 24 x 8, 60 x 2; 30,000,000 x 17 and 100,000,000 x 3; two abandons; invalid units; FEED, ALERT and RANKING sourced orders) over the REST API on the synthetic history `history-v1.sql` and records, per season, the inputs, the decisions with the verdict each unit was meant to get (derived from what the script sent; the HTTP answer only cross-checks it), every execution, ledger row, holdings and spans, turn prices and snapshots, the report, the stored score, the turn signals the noise item used, the fake engine's rank counts and the percentile request body. `tests/test_sim_parity.py` replays every season and compares each value exactly; a failure names the season and the first differing field. ## Reference bots / 기준 봇

`antlab_engine.bots` plays complete seasons offline with four rule bots over the season simulator, one scored `bot-run/1` record per bot: `random` (6-10 assets, integer weights, a coin-flip trade each turn; the null distribution), `static` (holds the start team of the random bot with the same index), `disciplined` (two assets per formation slot, rebalances when a slot is more than 5 points off its target, never sells after a fall of 8 percent or more and never buys after a rise of 8 percent or more; `disciplined-noguard` drops that guard) and `news` (starts from the disciplined team, sells all of an asset the turn's FALL or ECHO-down rows or the losers board name, buys the first three of RISE or ECHO-up rows by seq, then gainers, then attention, labelled `FEED(turn, seq)` or `RANKING`). All draws are integers from a SplitMix64 stream; the bots see only a `BotView` of the current turn, and a world with `feed` facts (`bot-world/1`) gets the feed and ranking board of `sim.feed` turn by turn from prices up to that turn, which also feeds the noise item of every bot's score. The feed facts must name exactly the pool's assets (else `FEED_INPUT`). The batch is offline only: no database, no network, no writes (`bots.world_pg` below is the one read-only database entry point). Batch: `uv run --frozen python -m antlab_engine.bots --world synthetic:7:30:60 --random 200 --static 1` writes `out/bots/<run>/runs.jsonl` and `manifest.json` (git-ignored), identical bytes for any `--workers`. `--world panel:INDEX[:ASSETS[:LENGTH[:simple|stationary]]]` draws a synthetic return-panel world from `--master-seed`, and `--counts [N]` (100..5000, default 2000; panel worlds only) then fills each record's rank `counts` and the section 6.3 result score from N engine paths. Probe bots for the score-weight validation: `newsmix-Q` (the disciplined bot that acts as the news bot on Q percent of its turns from turn 1, by an integer coin from a stream of its own; `newsmix-0` equals disciplined and `newsmix-100` equals news) and `redeclare` (the random bot of the same index that, after its orders, declares the multiple-of-5 formation nearest to its current weights by system position and never trades for it); batch flags `--newsmix 25,50,75` and `--redeclare N`. Bot rules are builder values: a change needs a bot `VERSION` bump (the pinned `decisionsSha256` tests fail first). / `antlab_engine.bots`는 시즌 시뮬레이터 위에서 규칙 봇 넷이 시즌을 오프라인으로 끝까지 진행하고 봇마다 점수가 매겨진 `bot-run/1` 기록 하나를 만든다: `random`(6~10종목, 정수 가중치, 매 턴 확률 매매; 기준 분포), `static`(같은 번호 무작위 봇의 시작 팀을 그대로 보유), `disciplined`(포메이션 칸마다 두 종목, 칸이 목표에서 5%p보다 벗어나면 재조정, 8% 이상 하락 뒤에는 팔지 않고 8% 이상 상승 뒤에는 사지 않는다. `disciplined-noguard`는 이 장치를 뺀다), `news`(규율 봇의 팀으로 시작해 그 턴의 FALL·ECHO 하락 행이나 하락 순위판이 가리키는 종목을 전량 매도하고, RISE·ECHO 상승 행(seq 순), 상승 순위, 관심 순위에서 앞의 3종목을 사며 `FEED(턴, seq)` 또는 `RANKING`을 단다). 난수는 모두 SplitMix64 정수 흐름이고, 봇은 그 턴의 `BotView`만 보며, `feed` 사실이 있는 세계(`bot-world/1`)는 그 턴까지의 가격으로 `sim.feed`의 피드와 순위판을 턴마다 받고 이것이 모든 봇 점수의 소음 항목에도 쓰인다. 피드 사실은 풀의 종목과 정확히 같아야 한다(아니면 `FEED_INPUT`). 배치는 오프라인 전용이다: DB·네트워크·쓰기 없음(아래 `bots.world_pg`가 읽기 전용 DB 진입점 하나다). 배치: `uv run --frozen python -m antlab_engine.bots --world synthetic:7:30:60 --random 200 --static 1`이 `out/bots/<run>/runs.jsonl`과 `manifest.json`(git 무시)을 쓰며 `--workers` 값과 관계없이 바이트가 같다. `--world panel:INDEX[:ASSETS[:LENGTH[:simple|stationary]]]`는 `--master-seed`로 합성 수익률 패널 세계를 만들고, `--counts [N]`(100~5000, 기본 2000, 패널 세계만)은 N개 엔진 경로로 각 기록의 순위 `counts`와 §6.3 결과 점수를 채운다. 점수 가중치 검증용 탐침 봇: `newsmix-Q`(규율 봇이 1턴부터 Q% 확률로 그 턴만 뉴스 봇처럼 행동한다. 확률은 자기 전용 흐름의 정수 동전이며 `newsmix-0`은 규율 봇, `newsmix-100`은 뉴스 봇과 같다)와 `redeclare`(같은 번호 무작위 봇이 주문 뒤에 현재 비중에 가장 가까운 5 단위 포메이션을 시스템 포지션 기준으로 선언하고 이를 위해 매매하지 않는다). 배치 플래그는 `--newsmix 25,50,75`, `--redeclare N`이다. 봇 규칙은 빌더 값이다: 바꾸면 봇 `VERSION`을 올려야 한다(고정한 `decisionsSha256` 시험이 먼저 실패한다).

Database worlds / 데이터베이스 세계: `antlab_engine.bots.world_pg.read_world(settings, base_date, seed, months=... | length=..., path_seed=...)` builds a `bot-world/1` with feed facts from the history inside ONE `REPEATABLE READ READ ONLY` snapshot of the SELECT-only role (the same role checks as `PostgresHistoryReader`): the pool of the base date with names and group codes, local returns and USD changes of each path month, the attention index of pool assets only (the table holds every asset of a block), and the events of each path month with the Java hidden rule (a type seen in fewer than 3 distinct `left(event_key, 6)` families from the replay start up to 1 January of the base year has no category). The path is either the given months (12, 24 or 60 distinct stored months inside the replay range) or the engine's own draw (`generate_months`) for a length and a path seed, so a world is the path a `p0-boot6-v1` season (the api's default path source) with that seed would walk, not an `m2-sb6-v1` engine-sourced one. The replay start is `ANTLAB_HISTORY_REPLAY_START`, the variable the api reads. A world is refused with a code and no month, asset or value: `FEED_EVENTS_UNREVIEWED` (a path month whose events are not reviewed, as Java), `FEED_REACTION_MISSING` (an event without a reaction, refused up front instead of at its turn), `FEED_INPUT` (a pool asset without a return, or a USD asset without an FX change, in a path month), `INVALID_ARGUMENT` (bad months). The batch CLI stays offline; `uv run --frozen python -m antlab_engine.bots.world_pg --base-date 2026-01-02 --seed 7 --length 12` (with the `ANTLAB_ENGINE_DB_*` variables) writes the world JSON under `out/worlds/` and the batch reads it with `--world <file>`. The role needs SELECT on `asset_group`, `asset_month_attention` and `month_event` (run `db/roles/antlab_engine.sql` again). Java parity: `src/test/resources/sim/parity/events-v1.sql` (fake events on top of `history-v1.sql`) is read by `FeedEventsParityFixtureTest` through the production `FeedInputReader` into the tracked `events-v1.json` (`ANTLAB_PARITY_WRITE=1` regenerates, refused on CI); `tests/db/test_world_pg_db.py` loads the same SQL into the scratch server and must give the same events, hidden flags, categories, order and refusals. / `antlab_engine.bots.world_pg.read_world(settings, base_date, seed, months=... | length=..., path_seed=...)`는 SELECT만 가진 역할의 `REPEATABLE READ READ ONLY` 스냅샷 하나 안에서(`PostgresHistoryReader`와 같은 역할 점검) 이력으로 피드 사실이 있는 `bot-world/1`을 만든다: 기준일의 풀(이름·그룹 코드 포함), 경로 달마다의 현지 수익률과 USD 변화, 풀 종목만의 관심 지수(표는 블록의 모든 종목을 담는다), 경로 달마다의 사건과 Java의 숨김 규칙(리플레이 시작부터 기준 연도 1월 1일 전까지 `left(event_key, 6)` 계열이 3개 미만인 유형은 범주가 없다). 경로는 주어진 달(리플레이 범위 안의 저장된 서로 다른 달 12·24·60개)이거나, 길이와 경로 시드로 엔진 자신의 추첨(`generate_months`)이므로 세계는 그 시드의 `p0-boot6-v1` 시즌(api 기본 경로 출처)이 걷는 경로이고 `m2-sb6-v1` 엔진 출처 경로는 아니다. 리플레이 시작은 api가 읽는 변수 `ANTLAB_HISTORY_REPLAY_START`다. 세계는 코드만 남기고 달·종목·값 없이 거부된다: `FEED_EVENTS_UNREVIEWED`(사건 검수가 안 된 경로 달, Java와 같음), `FEED_REACTION_MISSING`(반응이 없는 사건, 그 턴이 아니라 처음에 거부), `FEED_INPUT`(경로 달에 수익률이 없는 풀 종목, 또는 환율 변화가 없는 USD 종목), `INVALID_ARGUMENT`(잘못된 달). 배치 CLI는 오프라인 그대로이고, `uv run --frozen python -m antlab_engine.bots.world_pg --base-date 2026-01-02 --seed 7 --length 12`(`ANTLAB_ENGINE_DB_*` 변수 필요)가 세계 JSON을 `out/worlds/`에 쓰면 배치가 `--world <파일>`로 읽는다. 역할에 `asset_group`·`asset_month_attention`·`month_event`의 SELECT가 필요하다(`db/roles/antlab_engine.sql` 다시 실행). Java 대사: `src/test/resources/sim/parity/events-v1.sql`(`history-v1.sql` 위의 가짜 사건)을 `FeedEventsParityFixtureTest`가 운영 `FeedInputReader`로 읽어 추적하는 `events-v1.json`에 쓰고(`ANTLAB_PARITY_WRITE=1`로 재생성, CI에서는 거부), `tests/db/test_world_pg_db.py`가 같은 SQL을 임시 서버에 올려 같은 사건·숨김 플래그·범주·순서·거부를 내야 한다.

## Score-weight validation / 점수 가중치 검증

`antlab_engine.validation` tests offline whether the score weights make "random bots middle, disciplined high, news-following low" true, for the section 6.3 formula (`s63-v3`, result plus process) and the section 6.9 S formula, and searches a small weight grid. It is provisional until the real-history rerun (R-L): synthetic worlds have no momentum or reversal, so a proposal here changes no score constant and adopts nothing. Nothing is written to a database (history is read-only, and only for the DB profiles). Commands: `uv run --frozen python -m antlab_engine.validation run --profile ci|offline|sample-db|post-rl [--workers 1|2] [--master-seed N] [--out DIR]` (default `out/validation/<profile>-<seed>/`, git-ignored) and `... analyze DIR`. Profiles: `ci` (3 synthetic panel worlds, 12 turns, 12 assets, 20 reference and 20 evaluation random bots, 100 paths; under 10 s, covered by the default tests), `offline` (cells `p60s` 100 worlds of 60 turns with the simple path generator, `p60e` 60 worlds with the stationary generator, `p24s` and `p12s` 60 worlds of 24 and 12 turns; 30 assets, 2,000 paths, the full roster of 656 bots per world: 200 reference random 0..199, 200 evaluation random 200..399, 200 static 0..199, `disciplined`, `disciplined-noguard`, `news`, `newsmix-25/50/75`, and 50 `redeclare` bots paired with the evaluation bots 200..249), `sample-db` (20 database worlds of 24 turns) and `post-rl` (100 worlds of 60 and 60 of 24 turns after R-L); the two database profiles read worlds through `bots.world_pg` with the `ANTLAB_ENGINE_DB_*` variables and print "skipped" when those are missing. CPU budget (light resource mode): run one heavy job at a time under `nice`, `--workers 2` at most, peak memory about 1.5 GB at most; `offline` is estimated at about 55 CPU-minutes (roughly 16 s per 60-turn world with 656 bots). Workers are chunked by world, so a world's rank counts are drawn once, and the output is byte-identical for 1 and 2 workers. Each cell writes one `cells/<cell>.jsonl` (one line per bot: identity, stored s63 score, rank counts, every component to 12 places) and the run is resumable: a world is finished when its whole roster is in the file, finished worlds are skipped, a half-written world is run again, and a directory that belongs to another seed, profile, cell set or commit is refused. `run` ends by analysing the written files, never the values in memory, so `run` and `analyze` give the same `result.json` (`validation-run/1`, numbers as strings, camelCase) and a `summary.md` of at most 60 lines; `manifest.json` keeps the CPU and wall time and the peak memory. How the numbers are made: statistics are per world and then averaged over worlds; the 95 percent interval is a percentile bootstrap over worlds (2,000 resamples from the master seed; order statistics 51 and 1950 of the sorted resample means; statistics are rounded to 1e-9 first, so a bound of exactly 0 fails). The weight grid (step 0.05; S has 596 points, s63 has 9) is screened in float64 on the training worlds only (even world indices) as a superset of the exact result, then every candidate is checked exactly in `Decimal`; the draft weights are kept when they pass, else the passing point nearest to the draft is proposed, never the one with the largest separation. The proposal is then checked on the test worlds (odd indices) and on bots not used in selection (static C2, `disciplined-noguard` C6); `screenPassing` in the result is a screen count (an upper bound), and the proposal checks listed under `*-proposal` are in-sample (`worlds: all`), so read the held-out flags. If nothing passes the result says `no-passing-point` or `no-robust-point` instead of a proposal.

`antlab_engine.validation`은 섹션 6.3 공식(`s63-v3`, 결과+과정)과 6.9의 S 공식에서 "무작위 봇은 중간, 규율 봇은 높음, 뉴스 추종 봇은 낮음"이 가중치로 성립하는지 오프라인으로 검사하고 작은 가중치 격자를 탐색한다. 실제 이력 재실행(R-L) 전까지는 잠정이다: 합성 세계에는 모멘텀·반전이 없으므로 여기의 제안은 점수 상수를 바꾸지도 채택하지도 않는다. DB에는 아무것도 쓰지 않는다(이력은 읽기 전용이고 DB 프로필에서만 읽는다). 명령: `uv run --frozen python -m antlab_engine.validation run --profile ci|offline|sample-db|post-rl [--workers 1|2] [--master-seed N] [--out DIR]`(기본 `out/validation/<프로필>-<시드>/`, git 무시)과 `... analyze DIR`. 프로필: `ci`(합성 패널 세계 3개, 12턴, 12종목, 기준·평가 무작위 봇 각 20, 경로 100개; 10초 안, 기본 시험에 포함), `offline`(셀 `p60s` 60턴 100세계(단순 경로 생성기), `p60e` 60세계(정상 생성기), `p24s`·`p12s` 24·12턴 60세계; 30종목, 경로 2,000개, 세계마다 봇 656개 전체: 기준 무작위 0..199, 평가 무작위 200..399, 정적 0..199, `disciplined`, `disciplined-noguard`, `news`, `newsmix-25/50/75`, 평가 봇 200..249와 짝지은 `redeclare` 50개), `sample-db`(24턴 DB 세계 20개), `post-rl`(R-L 뒤 60턴 100세계와 24턴 60세계). DB 프로필은 `bots.world_pg`와 `ANTLAB_ENGINE_DB_*` 변수로 세계를 읽고 변수가 없으면 "skipped"를 출력한다. CPU 예산(가벼운 자원 모드): 무거운 작업은 한 번에 하나, `nice` 아래에서, `--workers 2` 이하, 최대 메모리 약 1.5 GB 이하; `offline`은 약 55 CPU분으로 추정한다(60턴 세계 하나에 봇 656개로 약 16초). 워커는 세계 단위로 나누므로 세계마다 순위 계수 경로를 한 번만 뽑고, 워커 1개와 2개의 출력 바이트가 같다. 셀마다 `cells/<셀>.jsonl` 하나를 쓰고(봇당 한 줄: 식별 정보, 저장된 s63 점수, 순위 계수, 모든 성분 12자리), 실행은 이어서 할 수 있다: 한 세계의 봇 전체가 파일에 있으면 끝난 것이고, 끝난 세계는 건너뛰며, 쓰다 만 세계는 다시 돌리고, 다른 시드·프로필·셀·커밋의 디렉터리는 거부한다. `run`은 메모리 값이 아니라 쓴 파일을 분석하며 끝나므로 `run`과 `analyze`의 `result.json`(`validation-run/1`, 숫자는 문자열, camelCase)이 같고, 60줄 이내 `summary.md`도 쓴다. `manifest.json`에는 CPU·벽시계 시간과 최대 메모리가 남는다. 숫자를 만드는 방법: 통계는 세계마다 구해 세계에 대해 평균하고, 95% 구간은 세계를 다시 뽑는 백분위 부트스트랩(기준 시드에서 2,000회; 정렬한 재표본 평균의 51번째와 1950번째 순서통계; 통계를 먼저 1e-9로 반올림하므로 경계가 정확히 0이면 실패)이다. 가중치 격자(0.05 간격; S 596점, s63 9점)는 훈련 세계(짝수 번호)만으로 float64로 걸러 정확한 결과의 상위집합을 만들고, 후보는 `Decimal`로 정확히 다시 검사한다. 초안이 통과하면 초안을 그대로 쓰고, 아니면 초안에 가장 가까운 통과 점을 제안하며 분리가 가장 큰 점은 고르지 않는다. 제안은 시험 세계(홀수 번호)와 선택에 쓰지 않은 봇(정적 C2, `disciplined-noguard` C6)으로 다시 확인한다. 결과의 `screenPassing`은 선별 개수(상한)이고 `*-proposal` 아래 검사는 표본 안(`worlds: all`)이므로 보류 항목 플래그를 읽어야 한다. 통과하는 점이 없으면 제안 대신 `no-passing-point`나 `no-robust-point`를 낸다.
