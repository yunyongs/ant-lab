# Engine / 엔진

The engine is an internal, deterministic FastAPI service (package `antlab_engine`). Its HTTP contract is `docs/api/engine.yaml`; every route except `GET /healthz` needs the `X-Antlab-Engine-Token` header.
엔진은 내부 전용 결정적 FastAPI 서비스(패키지 `antlab_engine`)다. HTTP 계약은 `docs/api/engine.yaml`이며, `GET /healthz`를 뺀 모든 경로는 `X-Antlab-Engine-Token` 헤더가 필요하다.

## Database / 데이터베이스

The engine reads history as the SELECT-only role `antlab_engine` (created by `db/roles/antlab_engine.sql`, see `db/README.md`; Java alone writes the database). Settings come from the environment: `ANTLAB_ENGINE_DB_HOST`, `ANTLAB_ENGINE_DB_NAME` and `ANTLAB_ENGINE_DB_USER` are required (a missing or blank value fails startup and names the variable, never the value), `ANTLAB_ENGINE_DB_PORT` defaults to 5432, and `ANTLAB_ENGINE_DB_PASSWORD` is optional locally and never printed. Startup and `/healthz` open no connection. `antlab_engine.history.PostgresHistoryReader.read(base_date)` returns one frozen snapshot from a single `REPEATABLE READ READ ONLY` transaction: months strictly before 1 January of the base year, the pool of that exact base date, and local returns and FX changes for those assets and months, all as `Decimal`. It refuses a superuser, a role that can create roles or databases or bypass row security, and any role holding a write privilege on any ordinary table outside the system schemas (`UNSAFE_DB_ROLE`), and errors never echo the cause, the password or a month. The connection uses explicit parameters, so libpq `PG*` variables (including `PGHOSTADDR`, `PGPASSWORD` and `PGGSSENCMODE`) and password files do not apply. Only `POST /v1/paths` returns months (internal route). / 엔진은 SELECT만 가진 역할 `antlab_engine`(`db/roles/antlab_engine.sql`이 만든다, `db/README.md` 참고. 데이터베이스는 Java만 쓴다)으로 이력을 읽는다. 설정은 환경변수에서 읽는다: `ANTLAB_ENGINE_DB_HOST`·`ANTLAB_ENGINE_DB_NAME`·`ANTLAB_ENGINE_DB_USER`는 필수(없거나 비어 있으면 시작이 실패하고 값이 아니라 변수 이름만 알린다), `ANTLAB_ENGINE_DB_PORT` 기본값은 5432, `ANTLAB_ENGINE_DB_PASSWORD`는 로컬에서 선택이며 출력하지 않는다. 시작과 `/healthz`는 연결을 열지 않는다. `antlab_engine.history.PostgresHistoryReader.read(base_date)`는 `REPEATABLE READ READ ONLY` 트랜잭션 하나에서 얼린 스냅샷을 돌려준다: 기준 연도 1월 1일 이전의 달, 그 기준일의 풀, 그 종목·달의 현지 수익률과 환율 변화를 모두 `Decimal`로 준다. 슈퍼유저, 역할·데이터베이스 생성 또는 행 보안 우회 권한이 있는 역할, 시스템 스키마 밖의 어느 일반 표에든 쓰기 권한이 있는 역할이면 거부하고(`UNSAFE_DB_ROLE`), 오류에는 원인·비밀번호·달을 싣지 않는다. 연결은 명시한 매개변수만 써서 libpq `PG*` 변수와 비밀번호 파일이 적용되지 않는다. 달을 돌려주는 경로는 내부 전용 `POST /v1/paths`뿐이다.

## Bootstrap parity / 부트스트랩 대사

`antlab_engine.bootstrap` is a bit-exact Python port of `p0-boot6-v1` (`SplitMix64` and the month selection of the Java `SimpleBootstrap`). `POST /v1/paths` serves it. `tests/test_vectors.py` reads the tracked Java vector file `src/test/resources/engine/p0-boot6-v1_vectors.csv` in place and compares every row character for character; a missing file fails the test. Changing any constant or formula changes the paths, so the engine version must change with the vectors. / `antlab_engine.bootstrap`은 `p0-boot6-v1`(`SplitMix64`와 Java `SimpleBootstrap`의 달 선택)을 비트 단위로 같게 옮긴 Python 라이브러리이며 `POST /v1/paths`가 이를 제공한다. `tests/test_vectors.py`는 추적되는 Java 벡터 파일 `src/test/resources/engine/p0-boot6-v1_vectors.csv`를 제자리에서 읽어 모든 행을 글자 단위로 비교하고, 파일이 없으면 시험이 실패한다. 상수나 식이 바뀌면 경로가 달라지므로 벡터와 함께 엔진 판을 올려야 한다.

## Stationary bootstrap / 정상 블록 부트스트랩

`antlab_engine.bootstrap.stationary` is the M2 path generator `m2-sb6-v1`: geometric block lengths (mean 6, cap 24), each block starts on the virtual calendar month (fewer than 3 candidates → ±1 month → any month), no month twice in one season, months of recent seasons avoided up to a caller threshold (a path that cannot meet it is still returned, best attempt first, with `overlap_met` false). The block length mean is 6 before the cap of 24 and about 5.92 after it. It is deterministic for a seed and pinned by `tests/vectors/m2-sb6-v1_vectors.csv`; `tests/gen_stationary_vectors.py` regenerates the file (review the diff as data). `POST /v1/paths` serves it (see below), and `p0-boot6-v1` stays unchanged. `uv run --frozen pytest -m slow -s tests/test_stationary_perf.py` prints the timing and overlap measurements. Supported history is up to about 1,200 months; one path costs under 0.15 s at the default 32 attempts even on the worst measured inputs, and the `attempts` budget is not capped in the library (256 attempts is about 1 s), so only the default is exposed over HTTP. / `antlab_engine.bootstrap.stationary`는 M2 경로 생성기 `m2-sb6-v1`이다. 블록 길이는 기하 분포(평균 6, 상한 24)이고, 블록마다 첫 달을 가상 달력의 월에 맞추며(후보 3개 미만이면 ±1개월 → 아무 달), 한 시즌에 같은 달을 두 번 쓰지 않고, 최근 시즌의 달은 호출자가 준 문턱까지 피하되, 문턱을 못 맞추면 가장 나은 시도의 경로를 `overlap_met` 거짓으로 돌려준다. 블록 길이 평균은 상한 24를 적용하기 전 6, 적용한 뒤 약 5.92이다. 같은 시드는 같은 경로를 내며 `tests/vectors/m2-sb6-v1_vectors.csv`가 고정하고, `tests/gen_stationary_vectors.py`가 이 파일을 다시 만든다(차이는 데이터로 검토한다). `POST /v1/paths`가 이를 제공하며(아래 참고) `p0-boot6-v1`은 그대로다. `uv run --frozen pytest -m slow -s tests/test_stationary_perf.py`가 시간과 겹침 측정값을 출력한다. 지원하는 이력은 약 1,200개월까지이고, 측정한 최악 입력에서도 기본 32회 시도에서 경로 하나가 0.15초 미만이다. 라이브러리는 `attempts`에 상한을 두지 않으므로(256회는 약 1초) HTTP에는 기본값만 노출한다.

## Paths endpoint / 경로 엔드포인트

`POST /v1/paths` (internal, token required; contract in `docs/api/engine.yaml`) returns one path of months for a seed from the history reader's snapshot. `engineVersion` selects `p0-boot6-v1` (fixed 6-month blocks, reproduces the Java vectors) or `m2-sb6-v1`. `seed` is a decimal string (signed 64-bit), `length` is 12, 24, 60 or 120, `baseDate` picks the snapshot, and the replay range stays 2007-01 up to the base year. `recentMonths` (`YYYY-MM`) and `maxOverlap` (decimal string, 0 to 1, default `"1"`) apply to `m2-sb6-v1` only; `conditional` must be false (regime-conditional paths are not built yet). The response has the months as `YYYY-MM`, the blocks, the overlap result, the attempt and a `historyDigest` (SHA-256 of the engine version and the sorted replayable months). Months and blocks are replay-only data: they are returned on this route only, never logged and never put into an error. Errors are `application/problem+json`: `INVALID_ARGUMENT` 400, `UNAUTHENTICATED` 401, `POOL_NOT_FOUND` 404, `PATH_TOO_LONG` 422 (the status Java uses), `HISTORY_UNAVAILABLE` 503, and `INTERNAL_ERROR` 500 (an unsafe database role is also answered this way, without role facts). `tests/test_paths_route.py` uses a fake reader; `tests/db/test_paths_db.py` runs the route against the isolated database. / `POST /v1/paths`(내부 전용, 토큰 필요, 계약은 `docs/api/engine.yaml`)는 이력 읽기 스냅샷에서 시드 하나의 달 경로를 돌려준다. `engineVersion`이 `p0-boot6-v1`(6개월 고정 블록, Java 벡터를 재현)과 `m2-sb6-v1`을 고른다. `seed`는 십진 문자열(부호 있는 64비트), `length`는 12·24·60·120, `baseDate`가 스냅샷을 정하며 재생 구간은 2007-01부터 기준 연도 직전까지로 그대로다. `recentMonths`(`YYYY-MM`)와 `maxOverlap`(0~1 십진 문자열, 기본 `"1"`)은 `m2-sb6-v1`에만 쓰이고, `conditional`은 false여야 한다(국면 조건 경로는 아직 없다). 응답은 `YYYY-MM` 달, 블록, 겹침 결과, 시도 번호, `historyDigest`(엔진 판과 정렬한 재생 가능 달의 SHA-256)이다. 달과 블록은 복기 전용 데이터라서 이 경로에서만 돌려주고, 로그와 오류에는 싣지 않는다. 오류는 `application/problem+json`이며 `INVALID_ARGUMENT` 400, `UNAUTHENTICATED` 401, `POOL_NOT_FOUND` 404, `PATH_TOO_LONG` 422(Java와 같은 상태), `HISTORY_UNAVAILABLE` 503, `INTERNAL_ERROR` 500이다(안전하지 않은 DB 역할도 역할 정보 없이 이렇게 답한다). `tests/test_paths_route.py`는 가짜 reader를, `tests/db/test_paths_db.py`는 격리 DB를 쓴다.

## Projection library / 예상 분포 라이브러리

`antlab_engine.projection.project` runs the current team as fixed quantities (buy and hold: no rebalancing, fees, interest or contributions) over N paths from `m2-sb6-v1`. Path seeds are derived from the season seed with a fixed domain constant, so the season seed is never reused and every portfolio sees the same paths. A different seed does not by itself guarantee a different path: `project` rejects a history that allows only one path (every seed would give it), but on a very short history paths can still repeat or coincide with the season's own. It returns value-multiple bands (5/25/50/75/95 %) for every turn, and at the summary turns (default 60 and 120) the end-multiple quantiles, the maximum-drawdown quantiles (5/10/25/50/75/95 %) and the number of paths whose maximum drawdown is strictly below the risk limit. It returns ratios only; Java converts to won. Quantiles are Hyndman-Fan type 7 with an exact index; evaluation uses element-wise numpy operations in sorted asset order and no matrix product, so the same inputs give the same bytes on one platform (`tests/test_projection_reference.py` compares them with a pure-Python evaluator bit for bit; `tests/test_projection_eval.py` pins the SHA-256 of a fixed input and, when it differs, prints the Python, numpy and wheel tag so arm64 and x86_64 runs can be compared; only arm64 has been checked). Decimal inputs are validated without rounding: a weight sum, a growth factor or a return that needs more than 200 significant digits is rejected, and so is a projection whose values overflow a float64 (`INVALID_ARGUMENT`, never NaN). Sizes are capped: a panel holds at most 1,200 months and 1,000 assets, a projection or seed list at most 5,000 paths. Months where a weighted asset has no return are never drawn. `POST /v1/projections` serves it (see below; `projection_version` `m2-pj-v1`). `uv run --frozen pytest -m slow -s tests/test_projection_perf.py` prints the stage timings (2,000 paths x 120 turns x 180 assets x 3 portfolios: about 0.6 s on the development Mac). / `antlab_engine.projection.project`는 현재 팀을 수량 고정(보유만 함: 재조정·수수료·이자·적립 없음)으로 `m2-sb6-v1`의 N개 경로에 돌린다. 경로 시드는 시즌 시드에서 고정 도메인 상수로 파생하므로 시즌 시드는 다시 쓰이지 않고, 모든 포트폴리오가 같은 경로를 쓴다. 시드가 다르다고 경로가 반드시 다른 것은 아니다: 이력이 경로 하나만 허용하면(모든 시드가 같은 경로를 낸다) `project`가 거부하지만, 아주 짧은 이력에서는 경로가 반복되거나 시즌 경로와 겹칠 수 있다. 매 턴의 평가 배수 분위 띠(5·25·50·75·95%)와, 요약 턴(기본 60·120)의 종료 배수 분위, 최대 낙폭 분위(5·10·25·50·75·95%), 최대 낙폭이 위험 한도보다 엄격히 깊은 경로 수를 낸다. 비율만 내고 원화 환산은 Java가 한다. 분위는 정확한 인덱스를 쓰는 Hyndman-Fan type 7이며, 평가는 정렬된 종목 순서의 numpy 원소별 연산만 쓰고 행렬 곱을 쓰지 않아 같은 플랫폼에서 같은 입력이 같은 바이트를 낸다(`tests/test_projection_reference.py`가 순수 Python 평가기와 비트 단위로 대조하고, `tests/test_projection_eval.py`가 고정 입력의 SHA-256을 고정해 두며 다를 때 Python·numpy·wheel 태그를 출력해 arm64와 x86_64 실행을 비교할 수 있게 한다. 지금까지 arm64만 확인했다). Decimal 입력은 반올림 없이 검증한다: 유효숫자 200자리를 넘는 비중 합·성장 배수·수익률은 거부하고, 값이 float64를 넘치는 예상 분포도 NaN이 아니라 `INVALID_ARGUMENT`로 거부한다. 크기에 상한이 있다: 패널은 최대 1,200개월 × 1,000종목, 예상 분포와 시드 목록은 최대 5,000경로. 비중이 있는 종목의 수익률이 없는 달은 뽑지 않는다. `POST /v1/projections`가 이를 제공한다(아래 참고, `projection_version` `m2-pj-v1`). `uv run --frozen pytest -m slow -s tests/test_projection_perf.py`가 단계별 시간을 출력한다(2,000경로 × 120턴 × 180종목 × 포트폴리오 3개: 개발용 맥에서 약 0.6초).

## Projections endpoint / 예상 분포 엔드포인트

`POST /v1/projections` (internal, token required; contract in `docs/api/engine.yaml`) projects fixed holdings over `n` paths (100 to 5,000, default 2,000) of `m2-sb6-v1` for 1 to 6 portfolios. A portfolio is a `key`, a `cash` share and up to 200 `weights` (`asset` as `MARKET:TICKER`, `weight` as a decimal string); weights plus cash must add up to exactly 1. `seasonSeed` (decimal string, signed 64-bit) only derives the path seeds, so the season's own path is never one of them; `horizonTurns` is 60 or 120, `riskLimit` is a decimal string such as `"-0.30"`, and `summaryTurns` (default 60 and 120) are capped at the horizon. The route reads the snapshot for `baseDate` from the history reader (US assets use the month's USD change, KR assets none) and draws only from months where every held asset has a return. The response gives, per portfolio, the bands for every turn and, per summary turn, the end-multiple quantiles, the maximum-drawdown quantiles, `breachCount` and `breachProbability`, all as decimal strings with eight fractional digits (rounded half up once). It has no months, no won amounts and no per-path values; `historyDigest` is the SHA-256 of the versions, the held assets and the eligible months with their growth factors. Errors are as for `/v1/paths`; the weights, the risk limit and the seed are checked before any history is read. A history that breaks the panel rules is a generic `INTERNAL_ERROR` 500. At most 3 projections run at once per process (`MAX_PROJECTIONS`, about 110 MB each in the worst case); a further call is answered `ENGINE_BUSY` 503 immediately (no queue) and may be retried. `tests/test_projections_route.py` uses a fake reader, `tests/db/test_projections_db.py` the isolated database, and `uv run --frozen pytest -m slow -s tests/test_projections_route_perf.py` prints the stage timings (2,000 paths x 120 turns x 180 assets x 3 portfolios: about 0.6 s on the development Mac, fake reader). / `POST /v1/projections`(내부 전용, 토큰 필요, 계약은 `docs/api/engine.yaml`)는 포트폴리오 1~6개의 고정 보유를 `m2-sb6-v1`의 `n`개(100~5,000, 기본 2,000) 경로에 돌린다. 포트폴리오는 `key`, `cash` 비중, 최대 200개의 `weights`(`asset`은 `MARKET:TICKER`, `weight`는 십진 문자열)이며 비중과 현금의 합은 정확히 1이어야 한다. `seasonSeed`(십진 문자열, 부호 있는 64비트)는 경로 시드를 파생하는 데만 쓰이므로 시즌 경로는 그중 하나가 아니다. `horizonTurns`는 60 또는 120, `riskLimit`는 `"-0.30"` 같은 십진 문자열이고, `summaryTurns`(기본 60·120)는 기간을 넘으면 버린다. 경로는 `baseDate`의 스냅샷을 이력 읽기에서 받아(미국 종목은 그 달의 USD 변동을 쓰고 한국 종목은 쓰지 않는다) 보유 종목 모두에 수익률이 있는 달에서만 뽑는다. 응답은 포트폴리오마다 매 턴의 분위 띠와, 요약 턴마다 종료 배수 분위·최대 낙폭 분위·`breachCount`·`breachProbability`를 소수 여덟 자리 십진 문자열(한 번 half up 반올림)로 준다. 달·원화 금액·경로별 값은 없고, `historyDigest`는 버전·보유 종목·자격 있는 달과 그 성장 배수의 SHA-256이다. 오류는 `/v1/paths`와 같고, 비중·위험 한도·시드는 이력을 읽기 전에 검사한다. 패널 규칙을 어기는 이력은 일반 `INTERNAL_ERROR` 500이다. 프로세스마다 동시에 예상 분포 3개까지만 실행하고(`MAX_PROJECTIONS`, 최악의 경우 개당 약 110 MB), 초과한 호출은 대기 없이 바로 `ENGINE_BUSY` 503으로 답하며 다시 호출하면 된다. `tests/test_projections_route.py`는 가짜 reader를, `tests/db/test_projections_db.py`는 격리 DB를 쓰고, `uv run --frozen pytest -m slow -s tests/test_projections_route_perf.py`가 단계별 시간을 출력한다(2,000경로 × 120턴 × 180종목 × 포트폴리오 3개: 가짜 reader로 개발용 맥에서 약 0.6초).
